## Actual final application screenshot index

| File | Real application view/state | Viewport/device | Build revision | Data/state shown | Verification notes |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

Final screenshots belong in `final-screenshots/` and must be captured from the running implemented application.

Include where applicable:
- Main Prompt Architect workspace
- Populated main page
- Contextual and pinned panels
- Pop-ups, menus, dialogs, drawers, overlays, and layovers
- Image editing mode
- Reference-image workflow
- Prompt DNA editing
- Character, monster, and vehicle workspaces
- Style, effect, wardrobe, vehicle, wrap, livery, and decal browsers
- History, branching, comparison, and enlarged viewer
- Different workspaces and layout modes
- Settings and provider connections
- Backup, restore, recovery, and accessibility controls
- Tablet or narrow-screen layout
- Loading, empty, save, offline, conflict, error, retry, and recovery states

## Image quality checklist

- [ ] Highest-quality practical source used
- [ ] Crisp and appropriately high resolution
- [ ] No avoidable stretching or visible compression artifacts
- [ ] No obvious malformed subjects, vehicles, or UI details
- [ ] Original source preserved where appropriate
- [ ] Optimized delivery derivative created where needed
- [ ] Responsive loading and memory impact considered
- [ ] Properly licensed, user-provided, or newly generated asset

## Important distinction
Never label a concept image or static mockup as an actual screenshot of the completed application.
